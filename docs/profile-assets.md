# Profile assets

The contribution heartbeat is rebuilt daily at 03:17 UTC, on relevant pushes to
`main`, and through **Actions → Update contribution heartbeat → Run workflow**.
The workflow uses its automatic `GITHUB_TOKEN`; no personal access token or
additional repository secret is required.

`scripts/build_heartbeat.py` reads GitHub's GraphQL contribution calendars from
2016 through the current UTC date. It sums daily counts into Sunday-based weeks,
including weeks that cross New Year, and renders the existing theme from
`scripts/heartbeat-template.svg`. The workflow token reads public contributions;
this is a contribution chart, not a count of commits alone.

The generator validates every requested day and its count before replacing
`assets/heartbeat.svg`. API failures keep the last successful image. Only that
generated asset is committed, and unchanged output produces no commit. The
workflow's own generated commits do not trigger another workflow run.

Run the offline checks with:

```sh
python3 -m unittest discover -s tests -v
```

To build locally, supply your own GitHub token through `GITHUB_TOKEN` and run:

```sh
python3 scripts/build_heartbeat.py --username elanthingal
```

A local token with additional user permissions may see more contributions than
the workflow token. The published image is generated by the workflow.

The visit badge is a separate live counter, not a generated asset. Its provider
counts image requests, which are affected by GitHub's image cache; it does not
measure unique people or every profile page view. The replacement provider starts
its own count and does not import the previous Komarev total.
